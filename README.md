## Tab `Front` — pairwise spread matrix

ตารางสามเหลี่ยมของทุกขาเทียบกับทุกขาที่อยู่ถัดไป ใช้ **แถวล่าสุดใน `Data`**
`A1` บอกวันที่**และเวลา**ของ snapshot นั้น เพราะวันหนึ่งมีสองรอบ

ช่อง `[แถว X, คอลัมน์ Y]` แสดง `yield% (±spread) (Nd)` เช่น `4.60% (+34.00) (23d)`

```
spread = Y_BID - X_ASK                          ขาย Y ซื้อ X
yield  = (Y_BID / X_ASK - 1) × 365 / gap        implied forward carry
gap    = TTM_Y - TTM_X                          spot นับ TTM = วันที่ snapshot
```

- **`gap` คือระยะระหว่างวันหมดอายุสองขา ไม่ใช่อายุคงเหลือของขาใดขาหนึ่ง** —
  นี่คือช่วงเวลาที่ carry ก้อนนั้นถูกคิดจริง ๆ
  ให้ spot นับเสมือนหมดอายุวันที่ snapshot แถว spot จึงเข้าสูตรเดียวกันโดยไม่ต้องแยกเคส
- ⚠️ **`Nd` ที่แสดง ≠ ตัวหารของ yield** — `Nd` คือวันคงเหลือของขาที่หมดอายุก่อน
  (ตัวบังคับให้ต้องปิดสถานะ) ส่วน yield หารด้วย `gap` เช่น `GCV6→GCZ6` แสดง `23d`
  แต่ 4.60% คิดบนช่วง 61 วัน — **อย่าเอา spread หารกับ `Nd` แล้วคาดว่าจะได้ %**
  ทั้งสองตรงกันเฉพาะแถว spot
- เป็น**สูตรล้วน** อ่านจาก `Data` โดยตรง มีแถวใหม่แล้วอัปเดตเอง ไม่ต้องรันอะไร
- **หัวแถว/หัวคอลัมน์ดึงจาก `Data` แถว 1 อัตโนมัติ** อ้างอิงด้วย**ชื่อขา**ไม่ใช่ตำแหน่ง
  เพิ่ม contract ที่ `Data` แล้วตารางโตเอง (รองรับถึง 12 ขา)
- **เรียงเป็นกลุ่มตามตลาด ไม่ได้เรียงตามคอลัมน์ใน `Data`** — spot → COMEX → TFEX
  แต่ละกลุ่มเรียงตาม TTM เพราะ contract ใหม่ต้องต่อขวาสุดของ `Data` เสมอ ถ้าเรียงตาม
  `Data` ตัว COMEX ใหม่จะไปต่อหลัง TFEX แยกตลาดด้วย prefix `CMX.` ถ้าเพิ่มตลาดที่สามต้องแก้
- **ขาที่เหลือไม่ถึง 7 วันก่อน TTM หลุดออกเอง** (`ROLL_OFF_DAYS`) — นับจากวันที่ของ
  snapshot ใน `A1` แล้วทุกอย่างเลื่อนซ้าย คอลัมน์และประวัติใน `Data` ยังอยู่ครบ
  ไม่รอถึง TTM เพราะโบรกเกอร์หยุดซื้อขายก่อน (`CMX.GCV6` ซื้อขายวันสุดท้าย 29 ก.ย.
  แต่ TTM 30 ก.ย.) และคู่ที่มีขานั้นอยู่ก็ทำจริงไม่ได้แล้ว ใช้ 7 วันเท่ากับ `MIN_GAP`
  เพราะช่วงนั้นช่อง spot ถูกตัด yield ทิ้งอยู่แล้ว รายงาน Chat ใช้เกณฑ์เดียวกันในการนับว่าขาไหน "ต้องมีราคา"
- ตั้งค่าครั้งเดียวด้วย `uv run python setup_front.py` (รันซ้ำได้ ไม่ซ้อนทับ)

### Chart ใต้ตาราง — scatter ทุกคู่

**ทุกช่องในตารางกลายเป็นหนึ่งจุด** (21 จุดสำหรับ 7 ขา) แกน y = yield,
แกน x = **term คือระยะระหว่างวันหมดอายุสองขา** ซึ่งเป็นตัวหารของ yield นั้นเอง
จุดหนึ่งจึงอ่านได้ว่า "ช่วงเวลาเท่านี้ ได้อัตราเท่านี้" โดยไม่ขัดกับตัวเอง
แถว spot ค่านี้เท่ากับ TTM ของ contract พอดี

- **จุดล้วน ไม่มีเส้น** — เส้นจะต้องลากเชื่อมคู่ที่ไม่ได้เกี่ยวอะไรกันนอกจากอยู่แกนเดียวกัน
- **แกน x ใช้ค่าสัมบูรณ์ของ gap** — gap ติดลบแค่บอกว่าขาคอลัมน์หมดอายุก่อน
  ซึ่งเป็นผลของตำแหน่งในสามเหลี่ยม ไม่ใช่ความยาวจริงของช่วง
  (ตัว yield ยังหารด้วย gap ที่มีเครื่องหมาย — ถูกแล้ว เพราะเศษกับส่วนกลับเครื่องหมายพร้อมกัน)
- **แยก 3 series** COMEX / TFEX / cross-venue — คู่ข้ามตลาดกระจายมาก (8.73% ที่ 29 วัน
  กับ 1.23% ที่ 31 วัน) เพราะเป็นส่วนต่างระหว่างตลาดมากกว่า carry แยกสีไว้จะได้หักลบในใจได้
- ใช้ **SCATTER** ไม่ใช่ LINE เพราะ LINE วางแกน x เท่า ๆ กันแบบ category
  ทั้งที่ term ห่างกันไม่เท่ากัน
- **แกน y ล็อก 0%–10%** ด้วยเหตุผลเดียวกับที่ล็อกช่วงสี — ตำแหน่งจุดต้องหมายถึง
  สิ่งเดียวกันในวันพรุ่งนี้ หลุดช่วงนี้จุดจะถูกตัด ไม่ใช่ปรับสเกล แก้ที่ `Y_AXIS`
- แยกตลาดจากชื่อด้วย `LEFT(name,4)="CMX."` ไม่ใช่การหาจุด เพราะ spot ชื่อ `XAUUSD.s`
  ก็มีจุดเหมือนกัน ถ้าเพิ่มตลาดที่สามต้องแก้ตรงนี้

### สี — อิง yield

Diverging น้ำเงิน↔แดง โดยมี**แกนกลางเป็นแถบเทา ไม่ใช่จุดเดียว**

| yield | สี |
|---|---|
| `-2% ถึง 2%` | เทา `#f0efec` — แทบไม่มี carry ให้จมไป |
| `±2%` ขึ้นไป | ไล่ทีละขั้น **ขั้นละ 1 จุด** รวม 6 ขั้น |
| `เกิน ±7%` | เข้มสุด (ตัดสีที่ปลาย ไม่ rescale) |

ฝั่งแดง match luminance กับฝั่งน้ำเงินทีละ step เพื่อไม่ให้ข้างใดข้างหนึ่งดูหนักกว่าทั้งที่ค่าเท่ากัน
(ต่างกันไม่เกิน 1.2%) และทุก step ตัวหนังสือดำอ่านออกเกิน 6.9:1

> เดิมตั้งไว้ `±4%` ถึง `±8%` ตอนที่ยังไม่มีข้อมูลสักวัน พอเก็บได้ 297 จุดพบว่า COMEX อยู่แถว
> 4.35% และ TFEX แถว 5.40% ทั้งตารางเลยกองอยู่ในหนึ่งในสามที่จางที่สุดของ ramp และทุกค่า
> ต่ำกว่า 4% — รวมถึงคู่ที่ได้ 2.08% กับ 3.94% — จมเป็นเทาสีเดียวกันหมด

`BANDS` คำนวณจาก `RAMP_UP`/`GREY_BAND`/`FULL_COLOUR` ไม่ได้พิมพ์คู่กันไว้ เปลี่ยน anchor
แล้วขอบแถบใน Sheet, `dashboard.html` และรูปที่ส่ง Chat ขยับตามพร้อมกัน

**สีเทาเข้ม `#dcdbd6` = yield ถูกตัดทิ้งเพราะ `|gap| < 7 วัน`** ช่องนั้นเหลือแค่ spread
หารรายปีด้วยช่วงสั้น ๆ ให้ตัวเลขไร้ความหมาย — `GCV6 → GOU26` ห่างกันวันเดียว
ส่วนต่าง $3.40 กลายเป็น -32%/ปี ซึ่งไม่ใช่ carry แต่เป็นส่วนต่างระหว่างตลาด
เทานี้เข้มกว่าเทากลางของ diverging (`#f0efec`) เพื่อไม่ให้สับสนกับ "carry ปกติ"

ค่าตัวเลขที่ขับสีอยู่ในคอลัมน์ `P:Z` ที่ซ่อนไว้ — Google Sheets ใช้ gradient กับเซลล์
ที่เป็นข้อความไม่ได้ จึงต้องแยกตัวเลขไว้ต่างหากแล้วใช้ conditional format แบบ custom formula

### ⚠️ เวลา contract หมดอายุ ให้ append คอลัมน์ใหม่ ห้ามแทนที่ของเดิม

`Front` อ่านแค่แถวล่าสุดจึงไม่กระทบ แต่ **`Data` เองจะเสียประวัติ** ถ้าเอา contract ใหม่
ไปทับคอลัมน์เดิม เพราะชื่อและ TTM อยู่ในแถว 1 ที่ทุกแถวใช้ร่วมกัน — หลังทับแล้วจะไม่เหลือ
ร่องรอยว่าราคาที่เก็บไว้ก่อนหน้าเป็นของ contract ตัวไหน และถ้าภายหลังทำกราฟย้อนหลัง
ค่าจะเพี้ยนทั้งคอลัมน์

ให้ปล่อย contract เก่าค้างคอลัมน์ไว้ (ช่องจะว่างเองหลังหมดอายุ และหลุดจาก `Front` เอง)
แล้วเติมตัวใหม่ต่อขวาสุด

**เพิ่ม contract ล่วงหน้าก่อนโบรกเกอร์ list ได้** — ใส่ชื่อกับ TTM ใน `Data` แล้วใส่ชื่อใน
`unquoted_symbols` ของ `config.json` job จะไม่ดึงราคา ช่องในชีตว่างรอไว้ รายงานไม่นับว่าขาด
และรูปที่ส่ง Chat ตัดขาที่ยังไม่มีราคาออก พอโบรกเกอร์ list แล้วค่อยเอาชื่อออกจากรายการ

ตอนนี้เหลือ `CMX.GCM7` (TTM 2027-05-28) ที่อยู่ในสถานะนี้ — `GOH27` โบรกเกอร์ list แล้ว
เมื่อ 1 ต.ค. 2026 และเริ่มดึงราคาแล้ว
ถ้าโบรกเกอร์ list ด้วยชื่ออื่น (เช่น `CMX.GCM27` แบบ `GCJ27`) ต้องแก้ชื่อในแถว 1 ให้ตรงด้วย

### `--snapshot`

ใช้ราคา ณ ตอนนี้จาก terminal แทนแถวที่ log ไว้ล่าสุด — **เรนเดอร์ครั้งเดียวเหมือนกัน**
ไม่วนซ้ำ อยากได้ค่าใหม่ก็รันใหม่

หัวข้อจะขึ้น badge **SNAPSHOT** พร้อมเวลาที่ดึง ส่วนโหมดปกติเขียนว่า **Logged** ตามด้วยวันที่
ทั้งสองโหมดเขียนไฟล์ชื่อเดียวกัน ถ้าใช้คำว่า snapshot ทั้งคู่จะแยกไม่ออกว่ากำลังดูอันไหน

- ต้องเปิด MT5 ค้างไว้ (เหมือน job รายวัน)
- ยังอ่านชีตอยู่ เพราะต้องใช้ TTM จากแถว 1 และกราฟประวัติ — ส่วน matrix กับ scatter
  ใช้ราคาสด
- ไม่เขียนอะไรลงชีต อ่านอย่างเดียว
- ยังไม่มี auto-refresh กับ `--open` ถ้าต้องการค่อยเพิ่ม

มี 3 ส่วน

1. **Matrix** — เหมือน `Front` แต่**ไล่เฉดต่อเนื่อง** ใช้สเกลและสี anchor ชุดเดียวกัน
   (import จาก `setup_front` จะได้ไม่หลุดจากกัน) แต่คำนวณสีระหว่าง anchor ได้
   บนชีต `4.41%` กับ `4.79%` เป็นสีเดียวกันเป๊ะเพราะอยู่แถบเดียวกัน ที่นี่แยกออก
2. **Scatter** yield เทียบ term แยกสีตาม COMEX / TFEX / cross-venue
3. **กราฟประวัติ** — สิ่งที่ชีตทำไม่ได้ ดู yield ของแต่ละ contract ขยับตามวัน
   จำกัด **30 snapshot ล่าสุด** (`HISTORY_DAYS`) เพราะข้อมูลโตทุกวัน ถ้าลากทั้งปี
   ความเคลื่อนไหวช่วงหลังจะถูกบีบจนดูไม่ออก
   ใช้เส้นทึบ/ประ แทนตลาดด้วย จะได้ไม่ต้องพึ่งสีอย่างเดียว

รันเมื่อไหร่ก็ได้ ไม่ต้องรอ `setup_front.py` — คนละเส้นทาง อ่าน `Data` ตรง ๆ ทั้งคู่

### `x = 0` หมายถึงวันที่ขาใกล้เลิกเป็น forward

ไม่ใช่วันเดียวกันในสองตลาด แต่เป็นเหตุการณ์ทางเศรษฐศาสตร์เดียวกัน จึงเอามาซ้อนแกนกันได้

|---|---|---|
| COMEX | first notice day | ยังเทรดต่ออีก ~26 วัน เส้นจึงลากเลยศูนย์ |
| TFEX | last trading day | ชำระเงินสดจบเลย เส้นหยุดที่ศูนย์ |

### สิ่งที่ต้องรู้ก่อนอ่านตัวเลข

**`copy_rates_from` ไม่เคยคืนค่าว่าง** เลยปลายประวัติมันคืนบาร์สุดท้าย ก่อนต้นประวัติคืน
บาร์แรก พร้อมราคาที่ดูปกติทุกประการ สคริปต์จึง**ตรวจเวลาบาร์ทุกครั้ง**ว่าตรงนาทีที่ขอ
ถ้าไม่ตรงทิ้ง — ถ้าไม่ทำ ตารางจะเต็มไปด้วยราคาซ้ำที่อ่านเหมือนข้อมูลจริง

**หน้าต่างที่ใช้ annualize คือ `far_expiry − max(วันนี้, near_expiry)`** ไม่ใช่ระยะห่าง
คงที่ระหว่างสองขา พอขาใกล้ผ่านวันหมดอายุของตัวเอง คู่นั้นเลิกเป็น calendar spread
กลายเป็น basis เทียบขาไกล หน้าต่างจึงหดตามอายุคงเหลือของขาไกล ถ้ายังหารด้วยระยะห่าง
คงที่ต่อไป ตลาดที่นิ่งอยู่ที่ 4.4% จะอ่านได้เป็นการไหลลงเหลือ 2.4%

**มีหนามจาก quote ค้าง 2 จุดจาก 297** (`GOZ26-GOU26` 5 ส.ค. และ `GOM26-GOH26`)
เกิดตอนตลาดวิ่งแรงและขาที่สภาพคล่องต่ำกว่ายังไม่ขยับตอน 10:00 ไม่ได้กรองออกเพราะเป็น
สิ่งที่ feed บอกจริง แต่อ่านเป็นสัญญาณไม่ได้

## `report.py` — ส่งรูปเข้า Google Chat

หลังเขียนแถวเสร็จ `simple_heatmap.py` จะ render `Front` เป็น PNG แล้วโพสต์เข้า space
ที่ตั้งไว้ในคีย์ `HeatmapSpace` ของ `..\.env\Path.env` โดยอัตโนมัติ

**ไม่ได้ทำเป็น task แยกใน Task Scheduler** — Scheduler ผูก task ต่อกันได้ทางเดียวคือ
trigger จาก event log ตอน task ก่อนหน้าจบ ซึ่งบอกไม่ได้ว่าจบแบบสำเร็จหรือ error
และยังต้องเดาว่าต้องหน่วงนานแค่ไหน เรียกในโปรเซสเดียวกันหลัง append รู้ผลแน่นอนกว่า

| สถานการณ์ | สิ่งที่ส่ง |
|---|---|
| ได้ราคาครบทุกขาที่ยังไม่หมดอายุ | รูป matrix |
| ขาดบางขา | ข้อความบอกว่าขาดตัวไหน ไม่ส่งรูป |
| backfill หลาย slot พร้อมกัน | ส่งครั้งเดียว ของ slot ล่าสุด (Front แสดงแถวสุดท้ายเสมอ) |
| slot ล่าสุดช้าเกิน `report_grace_minutes` | ไม่ส่งอะไรเลย เขียนลงชีตอย่างเดียว |
| โพสต์ไม่สำเร็จ | log ไว้แล้วผ่านไป ไม่ทำให้ job พัง — ตัวเลขลง sheet ไปแล้ว |

ที่ต้องเลิกส่งเมื่อช้าเกินกำหนด เพราะรอบที่ตามเก็บของเมื่อคืนตอนเช้าวันถัดไปคือการ
back fill ประวัติ ไม่ใช่ภาพตลาดตอนนี้ — ส่ง matrix ของเมื่อคืน 21:00 ตอน 9 โมงเช้า
แย่กว่าไม่ส่งเลย ข้อมูลยังลงชีตเหมือนเดิมทั้งสองทาง

"ครบ" นับเฉพาะขาที่ TTM ยังไม่ผ่าน ไม่งั้นพอ contract แรก roll ออก MT5 จะไม่รู้จัก symbol
นั้นอีกเลย แล้วรายงานจะเงียบถาวร

รันเองได้:

```bash
uv run python report.py              # ส่งเข้า space
uv run python report.py --out x.png  # render เฉย ๆ ไม่ส่ง
```

## กรณีข้ามวัน (เครื่องปิด / task ไม่ได้รัน / MT5 ไม่เปิด)

**ไม่ต้องทำอะไร — รอบถัดไปเก็บย้อนให้เอง** สคริปต์ดูวันที่ล่าสุดในคอลัมน์ A แล้วไล่เก็บ
**ทุก slot ที่ยังขาด** จนถึงตอนนี้ เขียนรวดเดียวเรียงตามเวลา

- **กันเขียนซ้ำ** — วันที่ที่มีอยู่แล้วในชีตจะข้าม รันกี่รอบก็ไม่เกิดแถวซ้ำ
  (ดังนั้นรันมือแทรกระหว่างวันได้ปลอดภัย)
- **เสาร์-อาทิตย์ / วันหยุดตลาด** — ข้ามอัตโนมัติ (เสาร์อาทิตย์ข้ามตามปฏิทิน,
  วันหยุดอื่นข้ามเพราะไม่มี tick เลย) ไม่เขียนแถวว่าง
- **`max_backfill_days`** (ค่าเริ่มต้น 10) จำกัดว่าย้อนได้ไกลสุดกี่วัน กันกรณีหายไปนาน ๆ
  แล้วไปดึงเกินช่วงที่ MT5 ยังเก็บ tick history ไว้ (เท่าที่ทดสอบย้อนได้อย่างน้อย 60 วัน)
- ถ้าหายไปนานกว่านั้นและอยากได้ครบ ค่อยเพิ่ม `max_backfill_days` หรือใช้ `--date` ไล่ทีละวัน

> ข้อควรระวัง: `--date` เขียนต่อท้ายเสมอ ถ้าใช้ backfill วันเก่ากว่าแถวล่าสุด
> ลำดับแถวในชีตจะไม่เรียงตามวันที่ (ข้อมูลถูก แต่ต้อง sort เองถ้าจำเป็น)

ตั้ง scheduled task (จันทร์–ศุกร์ มี 2 trigger คือ 10:00 กับ 21:00):

```bash
schtasks /create /xml SimpleHeatmap_task.xml /tn SimpleHeatmap
```

ยิงทดสอบทันที:

```bash
schtasks /run /tn SimpleHeatmap
```

### ไม่มีหน้าต่างเด้ง

task เรียก `.venv\Scripts\pythonw.exe` ตรง ๆ **ไม่ผ่าน `SimpleHeatmap.bat`** เพราะ .bat
เปิดหน้าต่าง cmd เสมอ และ `uv run` ก็เปิด console ของตัวเองซ้อนอีกชั้น ยิงเข้าตัว
interpreter เลยเป็นทางเดียวที่ไม่มีอะไรโผล่

ผลที่ตามมาสองข้อ

- **lockfile ไม่ถูกตรวจตอนรัน** (เสีย `uv run --frozen` ไป) ถ้าแก้ dependency
  ต้องรัน `uv sync` เอง
- **`sys.stdout` กับ `sys.stderr` เป็น `None`** ใต้ Task Scheduler — ตรวจแล้วเป็นทั้งคู่
  `setup_logger` จึงเพิ่ม console handler เฉพาะตอนมี stdout ถ้าไม่กันไว้
  `StreamHandler(None)` จะ fallback ไป stderr ที่ก็ `None` แล้ว log บรรทัดแรกโยน
  `AttributeError` ทันที — job ตายก่อนทำอะไรเลย

`SimpleHeatmap.bat` ยังอยู่สำหรับรันมือ ซึ่งเป็นกรณีที่อยากเห็น output อยู่แล้ว

## Config

`config.json` — `spreadsheet_id`, `sheet_name` (เว้นว่าง = ใช้ชีตแรก), `log_file`,
`snapshot_times` (รายการเวลาที่ต้องการ snapshot, เวลาไทย — ตอนนี้ `["10:00", "21:00"]`
เพิ่มลดได้ตามต้องการ), `lookback_minutes`
(ย้อนหาราคาถอยหลังได้กี่นาที — ตั้งไว้ 3 นาที ถ้าเกินนั้นเว้นว่าง เพราะต้องการให้ทุก
symbol อยู่ ณ เวลาเดียวกันจริง ๆ), `max_backfill_days` (ย้อนเก็บวันที่ขาดได้ไกลสุดกี่วัน),
`report_grace_minutes` (ช้าได้กี่นาทีก่อนที่จะเลิกส่งรายงาน — ค่าเริ่มต้น 30),
`unquoted_symbols` (ขาที่มีช่องแล้วแต่ยังไม่ต้องดึงราคา), `timezone`

`MT5_PATH` อ่านจาก `..\.env\Path.env` ที่ใช้ร่วมกันทั้ง repo

Log: `logs/simple_heatmap.log` (rotate 1 MB × 5)
